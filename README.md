# Мои Напитки

Android-приложение для домашней варки пива и сидра: склад и закупки, рецепты, варка с списанием по FIFO, себестоимость партий, этапы с прогнозом и напоминания.

## Стек

- Kotlin, Jetpack Compose (Material 3)
- Room (SQLite) для хранения
- WorkManager для ежедневных напоминаний об этапах

## Что умеет

- **Склад.** Закупки: название, вид, количество, сумма, дата. Остатки считаются по всем закупкам.
- **Рецепты.** Шаблон партии: ингредиенты и количества на один объём.
- **Варка.** Списание со склада по FIFO (сначала самая старая закупка), стоимость партии фиксируется сразу. Если не хватает ингредиента, варка не выполняется.
- **Этапы.** После варки создаются типовые этапы с плановыми датами. Отметка этапа с датой, температурой, плотностью и заметками пересчитывает прогноз следующих этапов.
- **Напоминания.** Раз в сутки приложение показывает уведомления о этапах, которые наступают в ближайшие сутки или просрочены.

## Структура

- `ui/`: экраны (`DrinkScreen`, `BatchDetailScreen`, `StockScreen`) и диалоги (рецепт, варка, отметка этапа).
- `data/`: сущности Room, DAO и `Warehouse` (закупки, рецепты, варка, этапы).
- `domain/`: чистая логика без Android: `FifoAllocator`, `CostCalculator`, `StageTemplates`. Покрыта unit-тестами.
- `notify/`: `StageReminderWorker` и расписание.

## Сборка и подпись

- Открыть папку в Android Studio и запустить конфигурацию `app`. Gradle wrapper ещё не добавлен, Android Studio создаст его при первой синхронизации.
- Подпись релиза: `keystore.properties` и `keys/alcohol-release.jks` лежат в репозитории по решению владельца.
- Обновления ставятся поверх установленной версии, если `applicationId` тот же и ключ тот же. `versionCode` поднимать при каждой новой сборке.

## Состояние

- Сборка и тесты ещё не запускались на Android SDK.
- Версия базы 1. После первой установки на телефон любое изменение таблиц требует новой версии и миграции.
- Сроки этапов (`StageTemplates`) типовые: их можно поправить под свой процесс.
